    Application-wide UI rollout report¶

    As of October 3, 2026. This report describes the current source-code integration, including the existing pilot areas. Acceptance of the installed Windows application is listed separately.

    Shared interaction concept¶

    The dashboard, left IconNavBar and right workspace remain in place. Action bars use one visible ribbon row with graphical buttons, clear text and translated tooltips. Icons measure 24 logical pixels; buttons are at least 40 pixels high. A subtle outer frame, centered group captions and one-pixel grey dividers provide consistent presentation.

    Record actions start on the left, followed by workflow, import/output and destructive actions in their groups. Refresh stays on the right. Existing form footers retain save/discard actions on the right and secondary actions on the left. Secondary ribbon actions move into More actions when space is limited. Selection-dependent disabled states, license visibility and existing signal connections are preserved.

    The central catalogue contains 256 distinct function icons and 295 label aliases. Each icon belongs to a function. The same function can reuse its icon across areas, such as Save. Different functions have different motifs: Activate, End, Terminate early, Link document, Link invoice, PDF/Excel/JSON export, Reset filter and Restore defaults are distinguishable. Ambiguous short labels such as Edit are further distinguished for amount lines, amount periods and invoice positions through stable widget IDs.

    Covered program points¶

    Ribbon covers both explicitly built shared bars and legacy action rows adopted on opening. Dialog/field actions receive the same icon, text, tooltip and sizing conventions while retaining their appropriate local position.     Read-only pages without commands, particularly role/permission information and applicable rule/information views, do not receive empty ribbon space. Checkboxes, input fields and native selection controls remain form controls. Field actions and page/step navigation receive icons without an unnecessary extra ribbon level.

    Implementation and evidence¶

    • ui_action_catalog.py: reviewed function identities, label aliases, presentation roles and context exceptions.
    • ui_action_symbols.py and ui_actions.py: vector motifs, shared buttons, grouped ribbons, form footers and legacy-row adoption.
    • app_i18n.py: integration for existing/new views and live language changes.
    • Existing widget IDs remain intact; missing IDs are derived from stable technical context and function. Permissions and business behavior are not inferred from translated label fragments.
    • All registered labels are present in the 23 language catalogues. Language-change tests verify stable icons, tooltips and accessible names.
    • Component tests distinguish all registered motifs at 100%, 125% and 150%. Qt component previews were additionally rendered at 1280 × 720 and 1920 × 1080 using these actual Qt scale factors; preview navigation is simplified.
    • Compact day/week views respond to changes in available workspace area; completely hidden action rows leave no empty ribbon. The dynamic traffic-case arrival notice retains its current count during opening and language changes.
    • Leasing and user-management pilot flows were verified against SQLite and a marked temporary PostgreSQL database, subsequently removed.
    • Enterprise scenarios and semantic ribbon inspection verify registered function icons, IDs, tooltips, accessible names, dimensions, order and overflow actions. Product architecture and language/documentation checks are part of final verification.
    • Final run: 452 passing component, localization and workflow tests, plus 4 passing SQLite/PostgreSQL pilot tests. Product architecture verification confirms 4 profiles and 27 features; documentation verification confirms 41 language pairs and 84 Markdown files.

    Acceptance limits¶

    The component preview at 100%, preview at 150% and complete function-icon sheet show the shared components. These are rendered Qt components, not captures of the installed application.

    Source-code rollout and automated component/workflow tests do not replace complete installed Windows end-to-end acceptance of every screen listed above. That acceptance, including real monitor scaling and the actual Windows cursor, remains outstanding. Restart the running application to load the changes. This report does not declare the previously observed cursor issue resolved.

    This rollout changes presentation of existing functions. It introduces no database schemas, license variants, global save transactions or blanket new validation/discard flows for forms that previously behaved differently. Existing save/discard and close-protection mechanisms remain in their respective workspaces.
